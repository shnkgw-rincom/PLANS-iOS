# Local Nutrition — カメラで食事を記録するiPhone・iPadアプリ

iPhone・iPadのカメラで撮影した食事の写真を保存し、端末内のQwen3-VLによる栄養推定値を同じ記録に追加します。

## 使い方

1. 「食事を撮影して記録」を押します。初回は端末でカメラへのアクセスを許可します。
2. 食事を撮影し、カメラ画面で撮影した写真の使用を確定します。
3. 原寸のJPEGと撮影日時が先に保存され、栄養解析が始まります。
4. 朝食・昼食・夕食・間食の区分、メモ、食べる分量を変更できます。変更後は保存ボタンを押します。
5. 「記録」から過去の写真・撮影日時・メモ・栄養推定値を確認できます。

撮影をキャンセルした場合は新しい記録を作りません。解析に失敗しても写真は残ります。履歴の「この記録を開いて編集・再解析」から再度解析できます。再解析は同じ写真に新しい解析履歴を追加します。

## 2B・4B・8Bの切替と解析用データ

「端末内で栄養を推定」のモデル選択で2B・4B・8Bを切り替えられます。2Bはアプリに同梱します。4Bと8Bは別途端末に追加してください。同じ写真を3モデルで順に再解析すると、元画像を1枚のまま、各モデルの結果・生の応答・実行時刻・所要時間・設定を記録します。失敗した解析も履歴に残します。モデルは切替時に1つずつメモリへ読み込みます。8Bは約5.4GBのモデルで、iPhone 17 Proでの実行可否はまだ実機で確認していません。

モデル選択の既定は4Bです。4Bはアプリに同梱していないため、端末へモデルフォルダを追加してから4B解析を実行してください。未追加のまま撮影した場合も写真は保存され、モデル追加後に再解析できます。2Bは手動で選択できます。

## 研究走行版との実画像比較

撮影後、解析で実際にモデルへ渡す正規化済みJPEGを、その解析回ごとに`Documents/model_inputs/`へ保存します。向き補正、長辺1024px以内への縮小、JPEG化を終えたファイルのバイト列を保存し、同じファイルのURLを推論へ渡します。ファイル名は`20260928_211504_123_000001_abcdef12.jpg`のように日時・写真番号・解析IDを含みます。再解析した場合も新しい入力JPEGを保存します。

各解析後に`Documents/analysis-log.jsonl`を更新します。1行が1解析で、`modelInputFilename`に`model_inputs/<ファイル名>.jpg`、写真番号、モデルID、解析モード、栄養値、失敗理由、生の応答、プロンプト、解析時間などを記録します。`ResearchExport/results.csv`と`ResearchExport/analysis-log.jsonl`にも入力ファイル名と解析モードを含めます。フォルダ一括解析のJSONにも各画像の`modelInputFilename`と解析モードを記録します。以前のアプリで解析した記録には、この入力JPEGは残っていないので項目は空です。

比較するときは、Finderの端末「ファイル」タブからLocal Nutritionの`model_inputs`フォルダと`analysis-log.jsonl`をMacへコピーし、入力JPEGを研究走行版の`Documents/images/appcheck/`へ入れて実行します。元写真が保存される`MealPhotos`とは別です。どちらのモードも長辺1024px以下に正規化した同じJPEGをMLXへ渡します。通常モードではMLX側で512pxにリサイズし、研究プロトコルモードでは`preprocessor_config.json`の画素上限で処理します。同一画像を比較するときは`model_inputs`のJPEGを双方で使ってください。2Bと4Bの出力を比較する場合は、モデル差も結果に影響します。

## 研究プロトコルモード

「端末内で栄養を推定」の「解析モード」で切り替えます。既定の「通常」は従来の利用者向け設定です。「研究プロトコル」は`LLM-Local/VLM-Local/BatchRunnerView.swift`の`BASE`をそのまま使い、L0・none条件（明示的な空のsystem）で、温度0、最大256トークン、反復ペナルティなし、JSON完成時の早期終了なしで生成します。入力画像は通常モードと同じ長辺1024pxの正規化JPEGです。MLX側の画像処理にはモデルフォルダの`preprocessor_config.json`から`min_pixels`/`max_pixels`（nullの場合は`size.shortest_edge`/`size.longest_edge`）を渡します。数値の読取は研究走行版の3段階（JSON → キー補完 → 正規表現）です。5項目が揃わない場合は画面上の推定を失敗とし、生の応答は残します。研究走行版の解析スクリプトは欠損値をnullとして扱うため、欠損を含む行まで比較するときは生の応答を使用してください。

撮影・単一画像・写真の複数選択・フォルダ一括解析で同じモードが効きます。モードはアプリ再起動後も保持され、一括解析開始時に固定します。一括解析の途中再開ではモデル・フォルダ・画像一覧に加えてモードも一致させるため、条件の異なる結果は混ざりません。`analysis-log.jsonl`と一括JSONには`analysisMode`（`consumer` / `research_protocol`）と読取段階の`parseStage`を記録します。論文への「同一出力」の記載には、更新版を実機に入れ、同一モデル・同一JPEGで研究走行版との値を照合する受け入れテストが必要です。

撮影時に写真番号を000001から自動採番し、元画像のファイル名にも番号を付けます。既存の記録はアプリ起動時に番号を割り当て、元画像のファイル名を変えずに記録を保持します。履歴の「解析用データを書き出す」を押すと、「ファイル」アプリの「このiPhone / iPad内 → Local Nutrition → ResearchExport」に`photos/000001.jpg`などの画像、`results.csv`、`records.json`ができます。CSVは解析1回ごとに1行で、写真番号、モデルID、栄養5項目、状態、時刻を持ちます。JSONには各解析のプロンプトと生の応答も含めます。CSVとJSONは画面から共有できます。画像は同フォルダの`photos`から取り出せます。

このMacには4B・8Bの重みがキャッシュされています。必要なモデルについて同梱の`prepare-models.sh 4B`または`prepare-models.sh 8B`を実行すると、アプリのソースとは別の`outputs/ModelTransfer`に転送用フォルダを作れます。Finderで接続端末を開き、「ファイル」タブのLocal Nutritionへそのモデルフォルダをドラッグし、アプリで「追加済みモデルを再確認」を押してください。別のMacに端末を接続していても構いません。端末の「ファイル」にモデルフォルダがある場合は、アプリの「モデルのフォルダを追加」から選ぶこともできます。空き容量が必要です。モデル転送用フォルダをGitHubへ公開する必要はありません。

## iCloud Driveフォルダの一括解析

iPhone・iPad共通の「フォルダの画像を一括解析」から、iCloud Driveまたは端末内の画像フォルダを選択できます。サブフォルダ内も含め、画像ファイルをファイル名順に1枚ずつ読み込み、選択中の2B・4B・8Bモデルで解析します。アプリ側に枚数上限は設けていません。写真アプリからの複数選択や、「ファイル」から画像ファイルの複数選択もできます。

結果は`このiPhone / iPad内 → Local Nutrition → BatchExports`に、例えば`Qwen3-VL-2B_research_protocol_20260928_211504_12345678.json`の名前で保存します。JSONにはモデルID、解析モード、開始・終了時刻、選択数、フォルダ名、各画像の相対パス、元画像のSHA-256、写真番号、栄養5項目、解析状態、エラー、生の応答、プロンプト、所要時間が入ります。iCloud側の同じ画像とMac上で照合するときは、相対パスまたはSHA-256を使えます。元画像は食事記録用にアプリ内にもコピーされます。

解析結果JSONは1枚終わるごとに更新されます。中止やアプリ終了後、同じフォルダと同じモデルを選ぶと、最後の保存時点から再開します。停止中に処理していた1枚は再解析される場合があります。フォルダ内の画像の追加・削除で一覧が変わった場合は新しい実行として記録します。完了した解析を同じモデルで再実行した場合も新しいJSONを作ります。失敗した画像はエラーをJSONに残して次へ進みます。iOSで長時間解析する場合は、電源につなぎ、アプリを前面に開いたままにしてください。結果JSONは画面の共有ボタンからiCloud Driveへ保存できます。端末の空き容量と発熱にも注意してください。

Xcode設定の対象デバイスは`1,2`で、iPhone・iPadの両方を含みます。同じアプリをそれぞれの端末にインストールします。

## 保存と書き出し

原寸の写真はアプリのDocuments/MealPhotosに個別のJPEGとして保存します。日時、食事区分、メモ、栄養推定値、分量倍率、モデルID、生の応答、プロンプト、解析時間はアプリ内に保存します。写真を保存する前に栄養解析は実行しません。結果は解析終了後に自動保存します。

履歴の詳細から原寸の写真を書き出せます。JSON出力にはメタデータと写真のファイル名を含め、写真は別ファイルです。JSONの日時はISO 8601形式です。アプリの削除で記録も削除されます。

画像解析にインターネットやAPIキーは不要です。写真をサーバーに送信する処理はありません。書き出しでは利用者が共有先を選びます。

## Xcode

LocalNutrition.xcodeprojをXcodeで開き、接続したiPhoneまたはiPadを実行先としてRunします。約1.7GBの2Bモデルを同梱しており、初回に端末へ転送されます。依存ライブラリの初回取得にはインターネットを使います。

- 対象：iOS / iPadOS 18以降。iPhone・iPad両方をインストール対象に設定しています。初版はiPad Air 11インチ（M4）とiPhone 17 Pro（iOS 26.6.1）にインストール済みです。iPhoneでの撮影・応答生成は利用者提供の画面で確認しています。
- iPhoneの縦画面では撮影・解析を上下に配置し、余白と分量操作を小さい画面に合わせます。
- iPhone・iPad共通版はXcodeでビルド成功済みです（2026年9月27日）。
- モデル：mlx-community/Qwen3-VL-2B-Instruct-4bit、リビジョン9c4f5209e57b31f4b9dfba735de3fb983739c9cc。4B・8Bは端末に追加した場合に選択可能です。
- MLX Swift LM：604fae710a4e3324346fc59e3845952350acd4b7。
- MLX Swift：0.31.6、swift-transformers：1.3.0。
- 写真保存と推論入力を分離。通常モードは推論用に長辺1024px以内に正規化したJPEGを解析回ごとに保存し、モデルの画像処理は512px、温度0、最大160トークン、反復ペナルティ1.1（直近64トークン）。研究プロトコルモードは上記の別設定です。
- 画像ごとに新しいセッションを使います。
- 数値5項目だけのJSONを要求し、最初のJSONオブジェクトが完成した時点で生成を止めます。古い記録のbasis（説明文）は読み込めますが、新しい応答には必須ではありません。

検証画像の選択画面と自動テスト起動は通常の撮影・記録画面から外しています。

開発用アプリの証明書が未信頼というエラーが出た場合、端末の「設定 → 一般 → VPNとデバイス管理 → 開発者APP」で、ご自身の開発用アカウントを信頼してから再実行します。Macを信頼する接続設定とは別の設定です。

## 栄養値

カロリー、たんぱく質、脂質、炭水化物、食塩相当量を推定します。写真からの値は概算です。重量、油、調味料、塩分は写真だけでは確定できません。

「食品成分表から計算する」を開くと、食品と可食部の重さを指定して別途計算できます。出典は文部科学省「日本食品標準成分表（八訂）増補2023年」（2026年3月訂正反映版）から引用。可食部100g当たりの値を使います。Trは計算上0、括弧付きの値は数値として使い、欠損の食塩相当量はデータ不足と表示します。

出典：https://www.mext.go.jp/a_menu/syokuhinseibun/mext_00001.html

## 確認状況

iOS向けのコードチェックと、写真の保存・読み込み、解析前の保存、解析失敗時の写真保持、日時の保持、再解析での重複防止、記録の更新・再読み込みのテストを実施しています。XcodeでiPad向けにビルドし、接続したiPad Airにインストール・起動済みです。実機のカメラで撮影した4032×3024pxのJPEGがDocuments/MealPhotosに保存されていることと、栄養解析・結果保存の完了ログを確認しました。

実機の保存領域全体をMacへコピーする確認は、iPadOSの画面スナップショットのアクセス制限で途中終了しました。撮影JPEGの取得は成功しています。記録の再読み込みは保存処理のテストで確認済みですが、実機を再起動した後の履歴表示は未確認です。

## 出力反復の修正（2026年9月27日）

利用者のiPhone画面で、basisの説明文が反復し、JSONが閉じないまま終了する不具合を確認しました。現在のソースでは、説明文を要求しない出力形式、最大160トークン、反復ペナルティ、完全なJSONでの早期終了を実装しています。未完成のJSONを数値として救済しません。失敗・中止した応答、プロンプト、解析時間、エラー、生成設定も同じ食事の記録に保存し、JSON出力で確認できます。

数値だけのJSON、途中終了した反復出力の拒否、文字列内の括弧・エスケープ、ストリームの途中で誤停止しないこと、失敗時の診断情報の保存・再読み込みをテストし、iOS向けのコードチェックも通過しています。修正版での実モデル推論はMac2のロックのため未確認です。iPhoneにインストール済みの初版には、この修正はまだ反映されていません。

修正版をXcodeから端末に更新した後、「記録」から該当する食事を開いて「この記録を開いて編集・再解析」を選び、「栄養を再解析」を押すと、元の写真で確認できます。出力形式の修正と栄養推定の精度確認は別です。包装の写真からは中身の重量を確定できません。

## モデル切替・連番出力の確認状況（2026年9月28日）

このソースについて、iOS向けSwiftコードチェック、連番の付与、写真とCSV/JSONの対応、3モデル分の解析履歴、失敗した解析の書き出しをテスト済みです。このMacのキャッシュに4B・8Bモデルの必要ファイルがあることも確認しました。研究プロトコル追加後の更新版は、2026年9月28日にXcode画面上で「Any iOS Device (arm64)」向けのビルドが成功し、接続したiPad Air 11インチ（M4）にインストールしてアプリのプロセスへ接続できました。4B・8Bの実機推論と端末からの書き出しは未確認です。

フォルダ一括解析の追加後、800件の入力名と結果を1つのJSONへ保存・再読み込みするテスト、途中結果の再開判定、画像ハッシュの安定性を確認しています。iPhone・iPad向けのSwiftコードチェックも通過しています。iCloud Drive上の実フォルダでの800枚連続推論は未実施です。

研究走行版との比較用に、推論へ渡すJPEGのバイト列が保存ファイルと一致すること、1解析1行のJSONLに対応する入力ファイル名が残ることもテスト済みです。4Bを既定にした更新版は、まだiPhone・iPadでの実機推論を確認していません。

4Bの転送用フォルダは`outputs/ModelTransfer/Qwen3-VL-4B-Instruct-4bit`に準備済みです（約2.9GB）。必要な設定・トークナイザー・重みファイルが揃い、参照先のないシンボリックリンクが残っていないことを確認しています。端末への4Bフォルダの転送は未確認です。
